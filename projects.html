RiskTrack

Grade: 18/20

Individual final-year project focused on using machine learning and data analysis as support for addressing academic dropout.

Context

The application was developed around the problem of predicting which students may be at risk of dropping out, using historical academic data.

Approach

CRISP-DM, exploratory data analysis, data preparation, decision-tree modelling, hyperparameter tuning and model evaluation.

Stack

R, Shiny, caret, rpart, tidymodels, PostgreSQL, DBI, RPostgres, pool, DT, pheatmap and RStudio.

Results

Final model evaluation included 0.77 balanced accuracy, 0.69 F1-score, 0.68 recall and 0.86 specificity.

See more details

The application supports model training, optional cross-validation, handling of missing values, prediction, CSV export and management of stored models and predictions. Models are stored as RDS files, while PostgreSQL stores related metadata.

The project also included a C4 architecture, accessibility testing and analysis of model limitations. RF04 (dataset/model compatibility validation) was not completed, and formal usability validation was not carried out due to time constraints.

The trained model lives inside the app itself rather than as a separate service: the same application handles training, evaluation and prediction. The decision tree was built with rpart and tuned via cross-validation, with particular weight given to recall during evaluation, since missing an at-risk student is more costly than a false alarm.

Travelex

Grade: 18/20

Group project for Distributed Systems Programming, designed to digitalise the informal practice of sending goods through travellers.

My role

Backend Developer and Project Manager.

Approach

Scrum with six documented sprints covering requirements, offers, selection, payments and delivery confirmation.

Stack

React, TypeScript, Node.js, Express, Firebase, Firebase Authentication, Stripe Connect, CometChat and external flight APIs.

Core flow

Traveller posts an offer → customer selects it → payment is held → delivery is completed → payment is released.

See more details

The platform validates flights through an external API, uses Firebase for authentication and data storage, and uses Stripe Connect for payment flows designed around delivery confirmation. Security considerations included identity checks, visible ratings and double confirmation of delivery.

The project was developed in an academic setting and was not validated with real users. Future work included real-world usability testing, stronger security mechanisms and additional tracking features.

Before development started, I explored UI mockups to work through the platform's look and feel, aiming for something modern but not futuristic, and focused on building trust between strangers exchanging money and packages.
